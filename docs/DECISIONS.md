# Решения

Формат: что решено, почему, какие были альтернативы. Пересмотренные решения не удаляются, а помечаются.

## D-001. Скрипты остаются обычными, без ES-модулей и сборщика
- **Решение:** новый код пишется теми же «обычными» скриптами с общей глобальной областью; расчётное ядро лежит в `src/js/core/` и не обращается к DOM.
- **Почему:** приложение открывается и как `file://`, и как один HTML-файл, и в Electron. ES-модули по `file://` в браузере не грузятся, а сборщик — новая зависимость и новый шаг сборки. Ограничение «не переписывать проект» тоже за это.
- **Альтернативы:** ES-модули + esbuild (чище границы, но зависимость и переделка всех семи файлов); UMD-обёртки (шум в каждом файле).

## D-002. Тесты — встроенный `node --test`, скрипты грузятся через `node:vm`
- **Решение:** `tests/load.mjs` создаёт контекст `vm`, выполняет в нём нужные скрипты ядра в порядке `index.html` и возвращает запрошенные глобальные имена. Запуск — `npm test`.
- **Почему:** ноль новых зависимостей; тестируется тот же код, что выполняется в приложении.
- **Альтернативы:** vitest/jest (зависимости, нужны модули); тесты в браузере через Playwright (медленно, тяжёлая зависимость).
- **Следствие:** в тестах `Path2D` заменён заглушкой (маршрут ремня строит контур сразу). Перенос построения контура в отрисовку — попутная задача.

## D-003. Рендер остаётся на Canvas 2D
- **Решение:** не переводить отрисовку на WebGL или SVG.
- **Почему:** приложение уже рисует на Canvas 2D; анимация течения — бегущий `lineDashOffset` по ломаной, это дёшево; сотни звеньев и труб Canvas 2D тянет при 60 кадрах в секунду.
- **Альтернативы:** WebGL (нужен свой слой текста и линий, оправдан только при тысячах объектов); SVG/DOM (медленнее при анимации).
- **Когда пересмотреть:** если кадр на демо-сцене экскаватора займёт больше 8 мс.

## D-004. Рабочая ветка `engineering-tool`
- **Решение:** вся работа идёт в ветке `engineering-tool`; `main` не трогается, поэтому workflow `Release` не срабатывает до слияния.
- **Почему:** релиз публикуется при пуше в `main` по версии из `package.json`; незаконченные фазы не должны попадать в релизы.

## D-005. Документация плана — на русском, README и CHANGELOG — на английском
- **Решение:** `docs/ROADMAP.md`, `PROGRESS.md`, `DECISIONS.md` ведутся на русском; README, CHANGELOG, комментарии в коде и сообщения коммитов — на английском, как в репозитории сейчас. Интерфейс по-прежнему двуязычный.

## D-006. Рабочая точка привода — скалярное уравнение на одну степень свободы
- **Решение:** кинематика приводов линейна по скорости источника, поэтому рабочая точка ищется бисекцией по одной неизвестной: скорости ведущего двигателя связной цепи. Остальные скорости получаются умножением на передаточные отношения из существующего линейного решателя.
- **Почему:** надёжно (характеристики монотонны на рабочем участке, бисекция не расходится), дёшево, не требует общего нелинейного решателя до фазы 2.
- **Ограничение:** одна цепь — один двигатель с характеристикой, ведущий. Несколько двигателей с характеристиками в одной цепи с двумя и более степенями свободы (дифференциал с двумя приводами) пока считаются так: первый ведёт, остальные работают как заданная скорость. Записано в ограничениях.
- **Альтернативы:** общий Ньютон по всем скоростям и моментам (появится в фазе 2 и сможет заменить это решение).

## D-007. Единицы существующего ядра приводов не переводятся в SI разом
- **Решение:** `model.js` и `solver.js` продолжают хранить геометрию в мм и скорости в об/мин; новые модули (`core/loads.js` и все новые домены) работают в SI и переводят значения на границе через `core/units.js`.
- **Почему:** одномоментный перевод старого ядра — крупная правка с риском регрессий без выигрыша для пользователя. Перевод идёт постепенно, по мере переезда кода в `core/`.

## D-008. Неактивные слои рисуются через второй холст
- **Решение:** в виде сверху слои ниже и выше активного рисуются на вспомогательном холсте и накладываются одним полупрозрачным листом (`FADE = 0.3`).
- **Почему:** код отрисовки деталей местами выставляет `globalAlpha` абсолютными значениями; общий множитель прозрачности потребовал бы переписать всю отрисовку. Два дополнительных `drawImage` на кадр стоят доли миллисекунды.
- **Альтернативы:** перевести отрисовку на относительную прозрачность (чище, но большая правка без пользы для пользователя).

## D-009. Правила слоёв
- **Решение:** указатель видит только детали активного слоя; вал принадлежит каждому слою, через который проходит. Заблокированный слой виден, но его детали нельзя ни выбрать, ни сдвинуть, ни добавить на него новые. «Только активный слой» — режим (`soloActive`), а не разовое скрытие остальных: он следует за сменой активного слоя. Клик по букве слоя в виде сбоку делает слой активным. Выбор детали в списке деталей активирует её слой.
- **Альтернативы:** разрешить выбор любого слоя кликом с модификатором (усложняет правило «клик проходит сквозь»).

## D-010. Проверка в браузере — отдельный скрипт, Playwright не зависимость проекта
- **Решение:** `scripts/smoke.mjs` собирает однофайловую сборку, открывает её в headless Chrome через Playwright, если он есть на машине, и проверяет запуск, шаблоны и правила слоёв. В `package.json` Playwright не добавлен, в CI скрипт не запускается.
- **Почему:** Playwright с браузером — сотни мегабайт; расчётное ядро проверяется `npm test` без него.

## D-011. Электродвигатель и «чёрный ящик» — отдельные типы деталей; старый «мотор» остаётся быстрым источником
- **Решение:** `emotor` — деталь-источник с характеристикой (по умолчанию асинхронный 0,37 кВт, 1320 об/мин), `machine` — деталь-потребитель с законом нагрузки, КПД и своим названием. Обе садятся на вал как любая деталь. Переключатель «Мотор» на любой детали остаётся как источник «задать скорость»; у любого источника можно выбрать вид характеристики. Переключатель «Нагрузка» вешает закон нагрузки на любую вращающуюся деталь.
- **Почему:** требование «источники — отдельные элементы» выполнено, а быстрые прикидки «кручу эту шестерню с такой скоростью» не усложнились.

## D-012. Поток мощности — по дереву кратчайших путей от источников
- **Решение:** мощность каждой нагрузки возвращается к ближайшему источнику по дереву обхода в ширину, делясь на КПД каждой ступени на пути. Момент на детали = мощность, проходящая через неё, делённая на её скорость. Если нагрузок на стенде нет, остаётся прежняя оценка: вся мощность мотора за вычетом потерь снимается на выбранном выходе; это написано в подсказке «откуда цифра».
- **Ограничения:** в замкнутых контурах (планетарная ступень, дифференциал) учитывается КПД одного зацепления на пути, циркулирующая мощность не считается; при нескольких источниках нагрузка относится к ближайшему. Для ±10–20 % этого достаточно.
- **Альтернативы:** полный расчёт моментов из уравнений равновесия каждого звена (появится вместе с кинетостатикой в фазе 2).

## D-013. Подсказка «откуда цифра» — плашка на чертеже по клику на число
- **Решение:** число с объяснением подчёркнуто пунктиром; клик открывает плашку с формулой, подставленными значениями, результатом и допущениями. Плашка обновляется при изменении сцены.
- **Альтернативы:** всплывающая подсказка по наведению (не работает на сенсорных экранах, исчезает при движении мыши).
