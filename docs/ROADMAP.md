# ROADMAP: Gear Bench → прикидочный инструмент по машиностроению

Рабочая ветка: `engineering-tool`. Состояние по задачам — в `docs/PROGRESS.md`, принятые решения — в `docs/DECISIONS.md`.

Цель: быстро собрать механизм из блоков, увидеть движение и получить прикидочные цифры (±10–20 %). Не САПР, не МКЭ/CFD, не точный решатель.

## 1. Что есть сейчас (v2.1.1)

- **Стек:** чистые HTML + CSS + JavaScript без зависимостей времени выполнения; Electron-оболочка (`main.js`); сборка `electron-builder` (Windows nsis/portable, Linux AppImage/deb) и однофайловый `gear-bench.html` (`scripts/bundle.mjs`). Релиз — workflow `Release` по версии из `package.json` при пуше в `main`.
- **Код:** семь обычных скриптов с общей глобальной областью (`strings`, `model`, `paths`, `solver`, `draw`, `templates`, `ui`), около 1700 строк.
- **Модель:** массив `parts` (деталь = тип, `x`, `y`, `layer`, размеры, флаги `motor/held/loose/mount`) и `links` (ремни и цепи). Контакты (зацепления, посадка на вал) не хранятся, а выводятся из геометрии при каждом `solve()`.
- **Решатель:** одна неизвестная скорость на жёсткую группу, одно линейное уравнение на контакт, инкрементное исключение Гаусса–Жордана (`Lin`); вторая такая же система — фазы зубьев. Момент и мощность — «вся мощность мотора минус типовые КПД ступеней на выбранном выходе».
- **Рендер:** Canvas 2D, вид сверху и полоса вида сбоку над ним. Вид сбоку почти не редактируется (только выбор).
- **Сохранение:** `localStorage`, формат `v: 2`, без миграций.
- **Тестов нет.**

## 2. Что мешает требованиям

| Требование | Что мешает сейчас | План |
| --- | --- | --- |
| Оба вида редактируемые | `hit()`/drag реализованы только для вида сверху; вид сбоку — полоса без своей вертикальной прокрутки | Вынести «проекции» в один интерфейс (world↔screen, hit, drag) и реализовать его для XY и XZ |
| Слои: клик только по активному | `hit()` берёт самую верхнюю деталь; нет блокировки; слой — просто номер | Слой становится объектом `{name, visible, locked}`; hit-тест фильтрует по активному слою; неактивные рисуются полупрозрачно |
| Порты и домены | Мотор — флаг детали с фиксированной скоростью; нагрузок нет; момент считается условно | Реестр доменов и портов, элементы-источники и потребители, баланс мощности и рабочая точка |
| Автоматические пары ТММ | Кривошип-ползун, кулачок, мальтийский крест — неразборные узлы | Новый домен `tmm`: звенья с шарнирами, пары как сущности, решатель положений |
| Трубопроводы и течение | Нет сущностей-линий с трассой | Сущность `pipe` (ломаная между портами), гидросеть, анимация штрихами |
| «Откуда цифра», предупреждения | Числа форматируются прямо в UI | Значение = число + формула + подстановка + допущения; реестр предупреждений |
| Единицы | Внутри мм, об/мин, Н·м вперемешку | Ядро новых доменов в SI; модуль `units` на границе с интерфейсом |
| Тесты ядра | Скрипты завязаны на глобальную область и DOM | Ядро без DOM; тесты через `node --test` и загрузчик на `node:vm` |
| Старые сцены | `v: 2` без миграций | Цепочка миграций `v2 → v3 → …` |

Рендер на Canvas 2D остаётся: его хватает и на анимацию течения (бегущий `lineDashOffset`), и на сотни звеньев. См. DECISIONS D-003.

## 3. Архитектура

### 3.1. Слои кода

```
src/js/
  core/        без DOM, покрыто тестами
    units.js     SI ↔ единицы интерфейса, форматирование
    explain.js   «откуда цифра»: значение + формула + подстановка + допущения
    warn.js      реестр предупреждений о применимости
    ports.js     домены и порты (усилие × поток)
    migrate.js   версии формата сцены
    loads.js     механические характеристики источников и нагрузок, рабочая точка
    nonlin.js    Ньютон с демпфированием для малых нелинейных систем (фаза 2+)
  strings.js model.js paths.js solver.js   существующее ядро приводов (постепенно переезжает в core/ и domains/)
  domains/     фаза 2+: tmm/, pipes/, hydro/, thermo/ — элементы, модели, обозначения, пресеты
  draw.js templates.js ui.js               интерфейс
tests/         node --test; load.mjs грузит скрипты ядра в контекст node:vm
```

Скрипты остаются «обычными» (общая глобальная область, порядок в `index.html`): так работает и `file://`, и однофайловая сборка, и Electron без сборщика. См. D-001.

### 3.2. Модель: одна сцена — две проекции

- Сцена трёхмерная в упрощённом смысле: у каждого элемента план `(x, y)` и слой (уровень по `z`, шаг `LP`). Вид сверху — проекция XY, вид сбоку — XZ. Виды не хранят ничего своего, кроме камеры.
- Интерфейс проекции: `toWorld(screen)`, `toScreen(world)`, `hit(screen) → элемент`, `dragStart/dragMove/dragEnd`. В XZ перетаскивание по горизонтали меняет `x`, по вертикали — слой (для вала — пролёт по слоям).
- Слой: `{ name, visible, locked }`. Взаимодействие — только с активным слоем; остальные рисуются с прозрачностью и пропускают клики. Вал, проходящий через активный слой, доступен на нём.
- Режимы вида сверху: «схема» (условные обозначения ГОСТ 2.770-68, гидравлика — ГОСТ 2.78x-96) и «реалистичный» (нынешняя отрисовка).

### 3.3. Порты

Домен = пара (усилие, поток), мощность = усилие × поток:

| Домен | Усилие | Поток |
| --- | --- | --- |
| `rot` вращение | момент, Н·м | угловая скорость, рад/с |
| `trans` поступательное | сила, Н | скорость, м/с |
| `hyd` гидравлика | давление, Па | объёмный расход, м³/с |
| `el` электричество | напряжение, В | ток, А (на уровне «мощность на выходе») |
| `th` тепло и газ | температура/энтальпия | массовый расход, кг/с |

Элемент объявляет порты (`id`, домен, положение, среда для `hyd`/`th`). Соединение портов разных доменов или сред запрещено либо даёт предупреждение (газовая линия к гидронасосу). Механические порты существующих деталей соединяются геометрией (зацепление, общий вал), гидравлические и газовые — трубами.

### 3.4. Решатель

Последовательность на каждом пересчёте:

1. **Кинематика приводов** — существующая линейная система скоростей (`Lin`).
2. **Рабочая точка** — баланс моментов, приведённых к валу источника: характеристика источника `M(ω)` против суммы характеристик нагрузок с учётом передаточных отношений и КПД; скалярное уравнение, бисекция.
3. **Рычажные механизмы (фаза 2)** — замкнутые контуры: уравнения связей пар `Φ(q) = 0`, Ньютон–Рафсон по положениям на каждом шаге, скорости и ускорения — из линейных систем с тем же якобианом; кинетостатика — линейная система реакций по группам Ассура или целиком.
4. **Гидросеть (фаза 3)** — узловые давления, нелинейные законы `Q(Δp)` элементов, Ньютон с демпфированием; режим клапанов и распределителей — дискретные состояния с пересчётом.
5. **Тепловые блоки (фаза 4)** — последовательный расчёт по контуру цикла.
6. **Алгебраические петли между доменами** (насос ↔ сеть ↔ двигатель) — итерации простой подстановкой с релаксацией, не более N шагов; при несходимости — предупреждение, а не молчаливый результат.

Динамика (разгон, маховик) — квазистатика плюс один-два интегратора там, где это нужно для наглядности (неравномерность хода, нагрев).

### 3.5. «Откуда цифра» и предупреждения

- `explain.js`: `val(name, valueSI, unit, {formula, subst, assumptions, source})`. Панель по клику на число показывает формулу, подставленные числа и допущения.
- `warn.js`: проверки регистрируются доменом, возвращают `{level, code, text, ids}`; интерфейс показывает список и подсвечивает элементы.

### 3.6. Формат сцены

`v: 3`: слои-объекты, источники и нагрузки. Каждая следующая версия добавляет функцию `vN → vN+1` в `migrate.js`; загрузка прогоняет цепочку. Для каждой версии — тест на образце сцены.

## 4. Задачи

Каждая задача — один–несколько коммитов; тесты проходят перед каждым коммитом.

### Фаза 0 — разведка и план
- [P0.1] Изучить репозиторий, написать ROADMAP, PROGRESS, DECISIONS.

### Фаза 1 — ядро
- [P1.1] Тестовая обвязка: `npm test` (`node --test`), загрузчик скриптов в `node:vm`, регрессионные тесты существующего решателя (двухступенчатый редуктор, планетарная ступень по формуле Виллиса, червячная, ремённая, цепная, реечная передачи, дифференциал, заклинивание). CI-workflow для тестов.
- [P1.2] `core/units.js`: SI внутри, об/мин, бар/МПа, кВт, °C, мм в интерфейсе; тесты.
- [P1.3] `core/explain.js`: значения с формулой, подстановкой и допущениями; тесты.
- [P1.4] `core/warn.js`: реестр предупреждений; тесты.
- [P1.5] `core/ports.js`: домены, порты, проверка совместимости; тесты.
- [P1.6] `core/migrate.js`: формат `v3`, миграция `v2 → v3`, тест на сохранённой сцене v2. Слои становятся объектами.
- [P1.7] Слои: клик только по активному слою, блокировка, полупрозрачность неактивных, «показать только активный»; тест hit-логики.
- [P1.8] `core/loads.js`: характеристики источников (асинхронный по формуле Клосса, постоянного тока, шаговый, «задать скорость», «задать момент») и нагрузок (постоянная, линейная, квадратичная, таблица); рабочая точка; тесты с аналитикой.
- [P1.9] Элементы «электродвигатель» и «машина — чёрный ящик» в модели, решателе и интерфейсе; баланс мощности вместо условного момента; демо-сцена.
- [P1.10] Панель «откуда цифра» в интерфейсе для передаточных отношений, скоростей, моментов, мощностей.
- [P1.11] Панель предупреждений; первые проверки: перегрузка двигателя, опрокидывание, самоторможение червяка, подрезание (z < 17).
- [P1.12] Проекции: общий интерфейс видов; редактирование в виде сбоку (перемещение по `x`, смена слоя, растяжение вала).
- [P1.13] Вид сверху «кинематическая схема» по ГОСТ 2.770-68 для существующих деталей; переключатель «схема / реалистичный».
- [P1.14] README, CHANGELOG, версия 3.0.0-alpha; проверка сборок Linux и Windows.

Приёмка фазы 1: все старые шаблоны и пример работают без регрессий (тесты P1.1 зелёные), сцена v2 открывается, двигатель с характеристикой выходит на рабочую точку с «чёрным ящиком», оба вида редактируются, слои ведут себя по требованиям.

### Фаза 2 — ТММ-конструктор
- [P2.1] `core/nonlin.js`: Ньютон–Рафсон с демпфированием, численный якобиан; тесты.
- [P2.2] Модель звеньев: стойка, кривошип, шатун, коромысло, ползун, кулиса, камень, произвольное N-шарнирное звено; шарниры и направляющие как точки привязки.
- [P2.3] Автоматические пары при соединении (вращательная, поступательная, высшая), удаление при разъединении, редактирование типа; обозначения по ГОСТ 2.770-68.
- [P2.4] Структурный анализ: формулы Чебышёва и Малышева, группы Ассура, лишние связи; тесты на шарнирном четырёхзвеннике, кривошипно-ползунном, кулисном механизмах.
- [P2.5] Решатель положений; скорости и ускорения; тесты против аналитики кривошипно-ползунного механизма и четырёхзвенника (Артоболевский, «Теория механизмов и машин»).
- [P2.6] Графики за цикл, траектории точек, планы скоростей и ускорений, условие Грасгофа, мёртвые положения, угол передачи.
- [P2.7] Кинетостатика: реакции в парах, уравновешивающий момент, силы инерции; тест «рычаг Жуковского».
- [P2.8] Маховик: коэффициент неравномерности, подбор момента инерции.
- [P2.9] Кулачки: законы движения, профилирование, угол давления, минимальный радиус; предупреждения.
- [P2.10] Мальтийский крест и храповик на новом ядре.
- [P2.11] Зубчатые: подбор чисел зубьев планетарных передач (соосность, соседство, сборка), смещение, подрезание.
- [P2.12] Демо-сцены 1 (пресс) и 2 (кулачковый привод клапана).

### Фаза 3 — трубопроводы и гидравлика
- [P3.1] Сущность «труба»: ломаная между портами, отображение в обоих видах, длина по трассе.
- [P3.2] Среды и совместимость портов; свойства масла, воды, воздуха.

- [P3.4] Фитинги: тройник, отвод, заглушка, переходник; автосоздание.
- [P3.5] Решатель гидросети.
- [P3.6] Визуализация течения: бегущие штрихи, цвет по давлению, легенда, застой, сброс.
- [P3.7] Элементы гидропривода: насос, мотор, цилиндр, распределитель (клик), дроссель, обратный и предохранительный клапаны, аккумулятор, бак; обозначения по ГОСТ 2.781/2.782.
